# Bot Authoring

Preserve supplied canon and the intended creative character of the work, including strangeness, asymmetry, intensity, moral ambiguity, and consequences. Do not normalize deliberate choices into generic harmony or an unrequested recovery arc.

Use the form the request needs. No psychology framework, cast grid, contradiction quota, trope catalog, or fixed number of examples is required. Deliver only the requested assets. A review does not itself authorize rewriting them.

Read a reference only when its contract matters:

- [SELF_INTRODUCTION.md](SELF_INTRODUCTION.md): the project's factual-profile plus voiced-monologue sheet format.
- [ARTIFACT_PLACEMENT.md](ARTIFACT_PLACEMENT.md): description, lorebook, persona, and state ownership.
- `writing-translation-guides`: a requested per-bot translation contract.

For implementation details, use the relevant shared skill: `writing-lorebooks`, `writing-cbs-syntax`, `writing-lua-scripts`, `writing-trigger-scripts`, `writing-regex-scripts`, `writing-html-css`, or `file-structure-reference`. Use `using-mcp-tools` for editor operations and preview/apply sequencing. These references describe the artifact's runtime, not a prescribed creative process.

Assess runtime claims against the actual card, preset, modules, target model, and available execution evidence. Distinguish a static prediction from an observed session result; do not claim long-session reliability from a text review alone.
