# Mythos Prompt Family Profile

Read this profile only for Mythos family design or maintenance.

## Promise and invariants

- Favor abstract, flexible narration guidance over brittle examples or forced beats.
- Preserve systematic character agency, perspective, relationships, memory, status, assets, and causality.
- Keep the prompt concise and non-duplicative; remove stale, narrow, or symptom-patching instructions.
- Preserve user authorship, viewpoint and information boundaries, mutually exclusive modes, and the family's intended creative intensity.

## Canonical and derived artifacts

Treat the artifact explicitly declared canonical by the current Mythos generation as the architecture owner. Do not infer canonical status from legacy `Source`, `Unified`, folder, or filename conventions. Markdown and `.risup` variants must remain philosophically aligned while justified provider prefill, identity, safety, or output-interface blocks may differ.

## Validation focus

Check authorship, viewpoint and focus, character state, memory and continuity, mode isolation, CBS variable and UI-name alignment, provider-only blocks, prompt item identity, and version alignment. A proposed change to these principles belongs to `prompt-family-development`; drift against an approved contract belongs to `prompt-family-maintenance`.
